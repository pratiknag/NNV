Nearest-Neighbor Vecchia Filter (NNV)
=====================================

Code to reproduce the results of "Nearest-Neighbor Sparse Cholesky Decomposition with
Applications to High-Dimensional Spatio-Temporal Filtering" and its Supplementary Material.

The code produces every numerical result, table and figure of the article:
  - the methodology figures of Section 2 (Figures 2 and 3),
  - the simulation study of Section 3 and Sections S5-S6 of the supplement,
  - the MIRS total precipitable water application of Section 4 and Section S7.

Three shell scripts do all the work:
  setup.sh             installs the Python and R packages
  run_simulations.sh   Figures 1-6 and S1-S6 (simulated data)
  run_application.sh   Table 1, Figures 7-8 and S7-S8 (MIRS data)


1. Requirements
---------------

  - Linux or macOS with bash, git and a C/C++ compiler
  - Python >= 3.10 (tested with 3.11.5)
  - R >= 4.1 (tested with 4.3.3; GPvecchia 0.1.8, fields 16.3.1, Matrix 1.6.5)
  - Arial or a metric-compatible font such as Liberation Sans (Figure 2 only)
  - No GPU is needed.

Hardware: all results were computed on an Intel Core i9-14900 CPU (32 threads) with 125 GB of
RAM. The exact Kalman filter of the application needs about 60 GB of RAM; everything else fits
in 16 GB.


2. Installation
---------------

Run every command from the folder that contains this file.

  bash setup.sh

This creates a Python virtual environment env/ with the pinned packages of requirements.txt
(PyTorch from the CPU wheel index) and installs the R packages GPvecchia, fields and Matrix
(GPvecchia from GitHub if it is not available on CRAN). Options:
  SKIP_PY=1 bash setup.sh        skip the Python part
  SKIP_R=1 bash setup.sh         skip the R part
  PYTHON_BIN=python3.11 bash setup.sh   choose the Python interpreter used for env/


3. Running the code
-------------------

Run the two pipelines one after the other (not at the same time):

  mkdir -p logs
  bash run_simulations.sh > logs/run_simulations.log 2>&1
  bash run_application.sh > logs/run_application.log 2>&1

On a remote machine, they can be started in the background so that they survive a logout:

  setsid nohup bash run_simulations.sh > logs/run_simulations.log 2>&1 < /dev/null &

Approximate run times on the hardware above:
  run_simulations.sh   about 6 hours
  run_application.sh   about 1.5 hours (of which about 40 minutes for the exact Kalman filter)

Options (environment variables, for both scripts):
  DRY_RUN=1     print every command without running it
  FORCE=1       regenerate the data and rerun every stage
  PYTHON=...    Python interpreter (default env/bin/python)
  SKIP_EXACT=1  (run_application.sh only) skip the exact Kalman filter, which needs about
                60 GB of RAM. Figures 8 and S7 are still drawn; Table 1 and Figures 7 and S8
                need the exact filter.
  FILTER_MODELS (run_simulations.sh only) data models of the large-n filtering run
                (default gaussian,poisson,gamma)

An interrupted run is resumed by starting the script again: stages whose output files exist
are skipped, and the tables and figures are always redrawn. Each stage writes its own log to
logs/.

All data sets and hold-out splits use fixed random seeds. Computation times (Figures 6, 7, S6
and Table 1) depend on the hardware and on other jobs running at the same time; multithreaded
floating-point sums can change scores in the last digits.


4. Data
-------

  - Simulations: generated by the code (src/R/generate_*.R).
  - Application: data/MIRS.csv.gz, the MIRS total precipitable water data used by Jurek and
    Katzfuss (2022), from https://github.com/katzfuss-group/vecchiaFilter
    (data-application/MIRS.csv). The code uses the inner 247 x 247 cells (n = 61,009) of the
    western 263 x 263 part of the grid over 11 consecutive days and holds out a random 10% of
    the observations at each time point.


5. What run_simulations.sh does
-------------------------------

  1. Figure 2 (src/R/patterns.R) and Figure 3 (src/python/basis_functions_comparison.py).
  2. Simulated data at n = 1,600 (40 x 40 grid), 10 data sets per data model (Gaussian,
     Bernoulli-logistic, Poisson, gamma): spatial-only data and advection-diffusion filtering
     data with T = 20 time points.
  3. HV and low-rank (LR) orderings and conditioning sets from GPvecchia
     (src/R/export_patterns_sweep.R); exact posterior and Kalman filter, NNV, its stages, HV
     and LR at five matched sparsity levels (src/python/sim_sparsity.py); Figures 4, 5, S2, S3
     and S5 (src/python/plot_sparsity.py).
  4. Exact and HV posterior means in GPvecchia (src/R/export_spatial_fields.R) and NNV
     posterior means for one logistic and one Poisson data set; Figures 1 and S1
     (src/python/plot_spatial_maps.py).
  5. Large n (grids of 100 x 100, 200 x 200 and 300 x 300) at about 80 nonzeros per row:
     spatial-only (src/python/large_n_spatial.py), filtering with n = 90,000
     (src/python/large_n_filter.py), HV and LR in GPvecchia for the time comparison
     (src/R/large_n_gpvecchia.R); Figures 6, S4 and S6 (src/python/plot_large_n80.py).


6. What run_application.sh does
-------------------------------

  1. Prepares the MIRS data and the hold-out split (src/python/mirs_prepare.py).
  2. HV and LR orderings and conditioning sets from GPvecchia (src/R/export_patterns_sweep.R).
  3. NNV, HV and LR filters at about 300 nonzeros per row, with held-out scores and filtering
     means and standard deviations (src/python/mirs_validate7.py).
  4. Exact Kalman filter with dense matrices (src/python/mirs_exact_full.py).
  5. Table 1, Figures 7 and S8 (src/python/mirs_exact_plot.py); Figures 8 and S7
     (src/python/mirs_maps.py).

The model parameters and sparsity settings of Section 4 are set at the top of
run_application.sh.

8. Folder layout
----------------

  setup.sh, requirements.txt         installation
  run_simulations.sh                 simulation pipeline
  run_application.sh                 application pipeline
  src/python/                        NNV, HV and LR filters (Numba), exact filters,
                                     simulations, application, figures
  src/R/                             data generation, GPvecchia patterns and fits, Figure 2
  data/MIRS.csv.gz                   application data
  README.md, assets/                 the same instructions in Markdown, with example figures

Main Python modules:
  large_n.py           NNV, HV and LR update and filter (Algorithm 1): IC0, Stage 3,
                       Newton with preconditioned conjugate gradients
  mirs_sparse.py       Stage 1 (prior and forecast), sparse approximate inverse,
                       evolution matrix
  sparse_functions.py  maximin ordering, sparsity patterns, reference implementation
  mirs_estimate7.py    application model and NNV filtering likelihood
